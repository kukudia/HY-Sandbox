# HY-Sandbox 夜间自主开发大纲

准备日期：2026-10-15。状态：规划完成，尚未启动本轮开发、NightDesk 或每日自动调度。

## 目标与产品边界

保持“模块化载具建造、物理战斗、可破坏世界与机器人回收”的产品方向，逐步打通建造 → 出发探索 → 交战与破坏 → 回收资源 → 返航入库 → 改装再出发。先解决影响这条链的稳定性和性能，再补齐有明确用途的小功能与表现。

自主选题允许项目内修复、系统重构、编辑器工具、可编辑资产和小玩法切片；不因夜间无人值守擅自改成另一种游戏。经济体系、永久世界存档、完整任务剧情、联网、无限地图和全物理建筑倒塌属于产品分叉，不默认纳入。

## 当前依据

- 最新入口是 DEVELOPMENT.md，以及 2026-10-15 的世界 Player 性能报告；旧 WorldResearch 和首次 NightDesk 交接描述的是研究阶段，不能据此重复开发已接入 Main 的功能。
- Main 已有有限大世界流式加载、建筑蓝图库、破坏与休眠恢复、加载遮罩、后台网格生成，以及 D3D11 Windows 验证包。
- 最新 Player 报告仍记录首次初始化约 301ms、跨区块移动约 64ms、退出约 71ms 的峰值。这些来自特定配置的短时测试，是待复测线索，不能当作所有场景的性能结论。
- 现有短时测试关闭随机敌机刷新；长期真实战斗、最大载具、高分辨率和其他 GPU 未验收。完整 Architecture 探针曾停在悬浮输出时序断言，需核对当前代码与探针契约。

## 阶段与验收门槛

阶段按依赖排序，不绑定“一晚做完一阶段”；每晚根据实际证据和剩余时间选择可完整交付的工作单元。

| 优先级 | 阶段 | 主要工作 | 完成门槛 |
| --- | --- | --- | --- |
| P0 | 建立可信基线 | 核对当前 Editor/Player、现有脏改动与恢复点；复查已知失败探针；固定种子、分辨率、载具与建筑配置 | 明确区分既有问题、新问题和测试错误；建立可复现路线与基线记录 |
| P0 | 会话稳定与卡顿 | 分别测量首次资源初始化、跨区块网格/碰撞提交、建筑启停、会话退出；按瓶颈处理预算、缓存和资源生命周期 | 同条件前后对照；主线程帧时间 P50/P95/P99、最大值及尖峰次数有记录；没有穿地、残留冻结、取消失效或退出污染 |
| P1 | 战斗、破坏与回收闭环 | 使用现有敌机、建筑、炮塔、货仓与机器人，跑通一段有限探索路线；修复索敌、遮挡、缺电、掉落和返航链中的实际问题 | 真实驾驶/输入、物理帧与 Player 运行覆盖；至少完成一次交战回收返航，并覆盖死亡、取消和再次出发 |
| P1 | 大结构与长期运行 | 分档增加载具块数、建筑、炮弹、Bot；持续跨区块交火、破坏、休眠恢复和多次进退会话 | 保存配置、时长、错误、帧时间和内存/对象数量趋势；异常有最小复现；压力档位不冒充支持上限 |
| P2 | 建造与信息体验 | 沿真实操作路线改善放置/连接反馈、选中与操作模式、资源信息、加载取消、缺电和失败原因提示 | 不破坏现有按键、手工布局和数据；真实输入与目标分辨率下可操作，提示准确、可读、不遮挡关键操作 |

性能暂以 1080p、60FPS 的 16.67ms 帧预算作为首轮候选目标，需在实际目标硬件复测后确定；720p 短时记录不能直接证明 1080p 达标。不通过降低物理正确性、世界数据完整性或隐藏测试失败换取数字。

## 首个夜间开发窗口

1. 建立起始 HEAD、脏文件清单和恢复点，读取最新项目记录；确认 CLI 连接的是此项目，记录 Editor 场景脏状态。运行本轮所需基线，不无差别重跑全部探针。
2. 先复核完整 Architecture 探针的悬浮时序问题。若是测试契约过时，按真实 FixedUpdate 顺序修正并回归；若是生产回归，先修复生产逻辑，不为通过测试削弱断言。
3. 固定路线复测世界进入、连续跨区块、退出与再次准备，定位最影响正常游玩的一个峰值来源。只有有测量证据时才优化，并执行同条件对照。
4. 时间充足时开始现有载具的短时真实战斗/回收巡航，优先处理阻断闭环的缺陷；大型新玩法留到稳定性门槛通过后。
5. 若剩余时间不足以完成实现与验证，只保存测量、复现和下一工作单元，不为填满时间仓促启动迁移。

## 每日运行与 08:00 收尾

- 时区固定为 Asia/Kuala_Lumpur（UTC+8）。每次启动落盘一个未来、带日期与偏移的明确截止时间；例如 10 月 15 日夜间启动，对应 2026-10-16T08:00:00+08:00。
- 默认从用户启动后持续工作至次日 08:00；07:30 停止接新需求，保存、验证、提交、写交接。总窗口不足 60 分钟时预留四分之一时间收尾。截止后仅允许必要的安全保存，不再开始开发。
- “每天 08:00 结束”不自动决定下一晚几点开始。当前只准备大纲；每日自动开工若后续启用，需要明确开始时间/有效日期。单轮续跑与次日晚间开工是两个不同安排。
- NightDesk 只负责黑色遮罩、公开进度与临时防睡眠；开发续跑使用可用的当前聊天 heartbeat，启动时核验实际工具、登记调度 ID 与仓库互斥。未成功注册就明确为仅当前会话执行。
- 首次正式启动先做必要的短时预演：检查准确实例、截止、进度读取、接管、释放电源请求和 Unity 后台真实帧推进；不能仅看遮罩在运行就认定游戏或 Codex 连续执行。
- Esc / Ctrl+Alt+F12 接管后保持桌面，不自动重新遮罩。用户 Unity 与 Codex 默认保留；不按进程名批量关闭软件。
- 每个完整单元仅做本地 commit，不 push、不发布。夜间规则优先于平时默认推送偏好；需要远程同步时遵循用户后续明确指令。
- 状态、锁、心跳和机器日志放在仓库外；计划、开发说明和精选验证证据进入项目。同仓库只允许一个写入者；收尾停用本轮续跑，下一晚不靠过期状态擅自重启。

## 自主决策与停止条件

每个工作单元写明需求证据、玩家收益、验收、风险和预估范围，再实现与验证。大改先保存可恢复点、检查序列化/资源/存档契约，完成必要迁移并清理替代实现。保留用户创作与有效数据，不把旧实现本身当作不可改变的边界。

同一路线连续失败 3 次且没有新证据就保存复现并换独立任务；登录、额度、唯一数据风险或关键产品方向阻塞时不猜测。没有独立可执行事项就提前交接，不用空轮询或无意义重构填满夜间。

## 验证与早晨交接

- 代码改动按项目要求执行可读性检查、dotnet build 和 git diff --check；按影响运行相应回归。纯文档更新不触发无关游戏构建。
- 新增/移动 Assets 经目标 Unity Editor 导入，保存并重载验证引用；涉及输入、物理、异步和生命周期必须跑真实运行。视觉改动单独检查画面，不用截图采集污染性能对照。
- 测试默认使用隔离数据目录；触及用户持久文件前记录清单和哈希。明确保留 Main 每次退出/死亡丢弃世界变化、正常返航货仓转存等现有行为，除非后续明确授权更改。
- 交接写入 Docs 下带日期的报告，并更新 DEVELOPMENT.md；包含完成项、commit、实际执行的验证、未验证项、失败/阻塞、保留状态和下一晚首选任务。
- 每早提供简短可操作结论：打开哪个场景/验证包、如何体验成果、还有什么缺口。阶段只有达到门槛才标完成，计划中的内容始终标为待开发。
