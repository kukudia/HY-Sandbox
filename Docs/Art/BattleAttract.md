# 待机战场规格与制作

用途：独立可编辑Unity场景 `Assets/Scenes/BattleAttract.unity`，初版空战演出与镜头观察；不读写个人蓝图，不参与金币/波次记录。

制作：`BattleAttractAuthoring.Create()`从已有5v5服务场景复制，移除其比赛、HUD和障碍布局；保留真实战斗池、灯光及地面。基地复用项目BastionHangars内置蓝图，8艘舰艇使用Finch/Pike/Manta内置蓝图（95/120/116模块）。生产武器/供电/导航负责实际交战；额外爆炸为纯视觉烟火，不调用伤害链。来源均为项目已有资源，沿用其原许可证与VFX依赖，无新增外部下载。

保守预算假设：Windows桌面、URP、约1300构造模块（不含机库展开外壳）、8艘舰艇；每帧最多补一艘，阵亡/越界后错峰补充，每65秒清场重启。额外烟火每2.2秒尝试一次，效果池活动实例达到128时抑制额外烟火；全演出场效果池总160/单模板24活动上限，省略视觉不修改伤害。场内炮塔每1.2秒错峰索敌，瞄准与开火仍逐物理步；正式战斗的原索敌参数不受影响。预算不是GPU性能保证。

可编辑源：场景保存基地锚点、8个出生点、6个烟火点、三对镜头起止点和焦点。`BattleAttractCamera`每7秒硬切，含基地仰视、空中穿越、舰队全景、动态友舰特写；镜头时长Inspector限制5–10秒。镜头位移平滑插值，构图和特写距离仍需真实渲染迭代。重建工具拒绝覆盖已有场景，日常调整直接改场景/Inspector，代码为可复现制作源。

当前状态：已导入、保存并真实Play，四镜头图已查看，天空/环境光已迭代。初始约7FPS，演出索敌错峰后短窗主线程约58ms；仍需长期与独立Player性能验收、场景美术继续细化。未来陨石雨不在本初版实现范围。

入口：主菜单Watch live defence，ESC返回。演出独立加载并临时接管战斗服务，退出恢复暂停的工坊和未保存原稿；不从演出写入个人存档。场景保存诊断Status Overlay引用，制作/修饰入口均修复缺失绑定，已有有效引用保持。
