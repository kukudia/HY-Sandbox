## 关键取舍

- UI 重排用**制作工具**（`HY-Sandbox/Siege/Apply Command HUD`）而不是手改YAML：所有位置/引用可复现，重复执行幂等；隐藏Main遗留对象只做 `SetActive(false)`，随时可在Inspector恢复。
- 战斗HUD严格按阶段切换，避免部署控件在战斗中占位；每帧只写两个 `anchorMax` 和一个 `CanvasGroup.alpha`，文本仍0.25秒节流。
- 精英/连击/无伤奖励都在**规则层**（`SiegeMatch`/`SiegeSession`）结算，HUD只读公开状态；HUD不参与规则。
- 修缮报价只在少数时机计算，不在每帧遍历388模块基地。
- 夜色外观改的是天空盒、雾、环境光和一个静态立方体缩放，**没有新增渲染批次或碰撞体**；`VisualEffectsManager` 的默认值与原常量一致，Main场景外观不变。

## 已知缺口与未验证

- **没有可靠的HUD帧成本对照**：外部逐帧采样受CLI往返开销影响，已放弃；编辑器内vsync与编辑器开销也淹没差异。本轮不声称任何FPS变化。
- 夜色下敌舰可读性只靠威胁标记补偿，未做人工对局验证；6个标记同时在场的重叠未观察。
- 进场信标与部分横幅的截图受CLI延迟限制（效果寿命<往返时间），只有直接调用与日志证据。
- Player与编辑器共享 `PlayerPrefs`（都在HKCU），同一台机器的纪录会互相影响；未做多局连续刷纪录的人工验证。
- 用户蓝图可能自带半格偏移的独立吊舱；部署/战斗表现未针对这类蓝图专门验证，只是把回归断言改为“不比出厂更碎”。
- 万模块压力场景、混合压力场与正式发布包未在本轮重跑；`SiegePlayerChecks` 的 soak 数据见本轮性能记录。
- 编辑器在 01:00 左右出现一次脚本编译后台卡死（`Internal build system error`），重启编辑器后恢复；期间未确认的场景改动已通过重载丢弃，`Temp` 目录被清空（临时证据文件不再存在，提交中的截屏引用为当时的路径）。
