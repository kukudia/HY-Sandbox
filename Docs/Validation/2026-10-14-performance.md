# 2026-10-14 性能优化与对比

基线：14496aa 的 PowerNetwork 原样冻结，只有类名和 Editor 条件编译包装不同。Unity 6000.3.11f1 Editor Play Mode，同一机器、同规模、两套相同布局，避免共享连接表污染缓存。未降低画质、物理频率或射击频率。

## 供电子系统 CPU

20次预热；40组AB/BA交替，每组3次更新。移动/请求变更发生在每次计时前，移动场景每次都会使拓扑失效。表为每次更新中位毫秒；包含真实组件调用、分配和状态提交，不包含对象创建和移动操作。

|---|---|---:|---:|---:|
|20/100|静态|0.52|0.10|约81%|
|20/100|移动|0.51|0.17|约67%|
|100/500|静态|10.73|0.56|约95%|
|100/500|移动|11.02|0.99|约91%|
|100/500|请求变化|9.79|0.58|约94%|
|300/1500|静态|97.94|2.49|约97%|

实现：精确身份/位置/连接距离快照决定拓扑重建，缓存连通分量；10米空间桶筛选连接与负载候选，再执行原盒范围检查。候选按登记顺序排序以保留原分配语义。功率请求、发电量、负载位置和状态仍每帧刷新。稠密同桶/超大覆盖范围仍可能退化为大量候选，未宣称所有布局线性复杂度。

原始样本、P95、环境及300轮等价检查见 [power-performance.json](2026-10-14-power-performance.json)。随机检查覆盖启停、范围、负载移动、发电量、请求变化及缓存命中，并逐项比较负载功率/工作状态/效率和连接边。

## 炮弹与图标

炮弹按Prefab复用，单Prefab闲置上限128，模拟结束销毁池根。回收恢复旧owner的IgnoreCollision，重新Launch恢复碰撞体、速度、位置与命中状态。查询满载时扩容重查并复用，避免每个密集帧退回All分配查询。炮塔每轮只查询一次owner刚体。

100组交替、每组10个创建/发射/回收周期：0.0261→0.00624ms，下降约76%。基线用Instantiate/Launch/DestroyImmediate，优化用Rent/Launch/Retire，隔离无owner；这是创建清理微基准，不等同原延迟Destroy帧，也未隔离旧版Launch和查询缓冲收益。热池复用仅4项检查，另有28项命中/后座及10项真实帧飞行回归。原始样本见 [projectile-pool.json](2026-10-14-projectile-pool.json)。

StatusIcon只在已有图标完全淡出且无异常时跳过投影；此前未建立root的正常对象本就跳过，并非全部正常对象都有新增收益。5项表现检查覆盖空闲关闭、淡出、重新显示和镜头墙体收回/自身过滤/恢复；UI收益未独立量化。

## 验证与剩余工作

Unity导入与编译通过；供电玩法32项、随机等价300轮、炮塔28项、真实帧飞行10项、复用4项、表现5项通过。dotnet build 0错误/4个既有警告；179脚本可读性检查及git diff --check通过。Main不保存临时对象，测试后退出Play。

GC.GetAllocatedBytesForCurrentThread在本机Unity主动分配4096字节仍返回0；JSON中的bytes全数无效，不作零GC结论。尚未做独立Player GPU/主渲染线程采样、长期密集交火内存、VFX overdraw和大型蓝图加载/断连重组压力验收。下一阶段先采集这些场景的CPU/GPU与GC Profiler，再决定VFX池化、UI遮挡分频、范围网格缓存与渲染质量分级，避免无证据降低画质。

复现：连接本项目Editor进入Play，运行 PowerPerformanceChecks.Run()（同步超过CLI 5秒时响应可能超时，但完成后会落盘）；PowerPerformanceChecks.StartFrames()异步采样，等待power-frames.json更新。ProjectilePoolChecks.Run()与PresentationPerformanceChecks.Run()分别生成报告。测试对象均临时创建，不保存场景。
