# EnemyController 避障试验场验证

## 可复现入口

- Unity 6000.6.8f1 打开 `Assets/Scenes/EnemyAvoidanceLab.unity`，直接 Play。
- Game 面板可选 Single wall、U trap、Slalom、Narrow gate；Run all 连续运行四组。障碍和完整 Finch 舰体均为已保存、可编辑的真实场景对象。
- BlocksParent Prefab 的 Draw Debug、Main/Siege/WorldLab 的友敌 AI 显示均已开启；Scene/Game 需保持 Gizmos 开启。蓝色为 NavMesh 路径，青色为目标，紫色/白色为期望/平滑驾驶输入。
- 使用生产 EnemyController、Rigidbody、推进器和供电。测试中禁用武器、固定目标舰、将碰撞伤害系数设为 0；保留实体碰撞与惯性。每次重试仅在起点重置试验舰，飞行期间没有额外施力、传送或速度钳制。
- 每组超时 90 秒，首次进入目标水平距离 22 米后继续观察 2 秒；22 米为 18 米交战距离加 4 米舰体容差，属于接敌判定。接触数统计布局障碍的 OnCollisionEnter，过滤地面。
- 结果写入 `Temp/EnemyAvoidanceLab/trials.json`。Run all 清空本轮结果；单独重试追加记录。

## 调优依据与行为

初始实船试验暴露出净空不足、侧滑和拐点切墙。原来的 2 米净空不足以容纳 Finch；自动净空现在取自主舰实际水平碰撞范围，加 2.5 米安全余量，并保留 Inspector 最低半径。共享导航采用最大自主舰净空，因此比实际舰宽更窄的门选择外侧绕行，不以穿门为成功标准。

驾驶按 0.1 秒刷新，目标扫描频率保持独立；参考速度 6 米/秒、估计减速度 3 米/秒²，通过原有输入抵消侧滑并在弯前减速。切换拐点必须确认下一段在膨胀后的 NavMesh 上可直达；初次烘焙未完成时等待。

初始基线的单墙在 90 秒后仍距目标 63.7 米、37 次障碍接触；其他基线提前中断或使用不同超时，不能作为同条件耗时对照。

## 实际验证

最终正常速度实船结果见下表。Time.timeScale=1，fixedDeltaTime=0.02；与保存场景一致的安全余量 2.5 米，运行净空约 12 米。

| 布局 | 到达耗时 | 结束时目标距离 | 飞行路程 | 障碍接触 |
| --- | ---: | ---: | ---: | ---: |
| Single wall | 28.8 秒 | 16.3 米 | 115.1 米 | 0 |
| U trap | 31.2 秒 | 15.7 米 | 130.6 米 | 0 |
| Slalom | 37.8 秒 | 14.8 米 | 144.1 米 | 0 |
| Narrow gate（外侧绕行） | 36.4 秒 | 16.3 米 | 157.9 米 | 0 |

同一轮生产代码在连接的 Unity Editor Play Mode 中通过：导航/炮塔遮挡 17 项，AI 回归 21 项。包含墙后目标不锁定、自身构筑墙板遮挡、失去视线立即解锁、断开网格停在可达边缘、禁用导航注销以及无网格回退等检查。

退出 Play 后重新打开已保存场景：2 艘舰、试验舰 95 个模块/21 个推进器、4 组布局、目标引用完整、缺失脚本数 0、安全余量 2.5 米、接敌判定 22 米、Debug 开启。额外执行 Edit Mode 临时 Finch 制作/连接重建及清理，95 个模块生成成功、无 Error/Exception；连接视觉对象在编辑态使用 DestroyImmediate，修复制作场景时的非法 Destroy 调用。临时探针未保存。

静态检查：CodeReadability 419 个脚本、0 差异、0 错误；`dotnet build HY-Sandbox.sln --no-restore` 0 错误、36 个既有警告。本机缺少 global.json 固定的 9.0.318，命令从项目父目录使用已安装的 9.0.320 执行，不修改 SDK 配置。静态编译不代替上述实船飞行。

## 后续调优：遇障优先爬升

默认先检查目标/警戒方向前方50米的静态障碍。完整舰体包围盒先扫前方，再验证垂直上升与升高后的前进走廊；只在两段净空均可用时抢占NavMesh水平绕行。按障碍顶部、舰体底部偏移和3米净空确定高度，相对正常悬浮目标高度最多增加32米。高障碍、顶棚或高处通道受阻均回退水平寻路。触发器、自身舰体与动态载具不作为静态翻越目标，动态避障仍由原局部球扫负责。

升高不足时参考前进速度降为15%，用原推进器补偿侧滑、减速；维持高度直到整舰越过障碍远端，再恢复常规悬浮目标。此优先级也高于接敌距离内的横移。保持通过HoverFlightController施力，不直接修改位置/速度。

连接Editor的Play Mode检查：新增7项（可翻越高度、舰尾通过前保持、通过后释放、头顶顶棚回退、高处走廊受阻回退、最大爬升限制、触发器/自身过滤）通过；原17项导航/炮塔检查和21项AI回归通过，共45项。静态检查420脚本、0差异/错误；编译0错误、36个既有警告。

正常速度（timeScale=1、fixedDeltaTime=0.02）Finch实船四组均到达、零障碍接触；单墙27.6秒、U形27.6秒、错列墙37.7秒、窄门27.6秒。运行观察到U形、错列墙及窄门均主动抬升，墙顶20米时悬浮目标约27米；窄门优先翻越门旁墙体。结果仍按水平22米接敌阈值判定，不代表已在目标旁完成下降/停稳；测试舰碰撞伤害系数仍为0。

### 当前验证边界

本轮覆盖单艘 Finch、平面静态高墙、四种布局；未验证大型混编舰队、动态障碍密集会车、流式世界长时间运行及性能预算。共享最大净空可能使小舰也绕开本可通过的通道；需要分尺寸导航时应进一步拆分 Agent 类型。NavMesh 仍是地面走廊辅助飞行，不是完整三维空域规划。
