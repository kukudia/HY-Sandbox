# Siege战斗流程与UI修正（2026-11-17）

环境：Windows、Unity 6000.6.8f1，连接Editor修改真实Prefab/场景。恢复点：`Temp/SiegePolishBackup-20261117-150542`保存原始场景、动态字体资产和工作区补丁；每次迁移另存唯一时间戳的场景/Prefab备份。保留现有共享HUD实例覆盖，移除用户要求淘汰的Construction Controls与Return。未重写玩家存档；动态字体缓存及UserSettings不作为本轮代码提交。

## 修复与行为

- Debug的行背景由共享制作器设成`raycastTarget=false`，Toggle自身没有可命中的Graphic；现原位修正七行背景，制作器同步修正。真实EventSystem.RaycastAll加PointerClick验证射线命中与实际DebugManager状态。
- DestroyManager原先只把旧SiegeSession认作死亡所有者；新版AI友舰死亡可能误弹Main玩家死亡面板。新版Siege模式现在同样拥有死亡结果。核心损失经Stage幂等结算，爆炸后等待1.5秒显示独立失败面板；时限失败同样走核心建筑销毁主链，待结算收益清零。
- 战斗准备5秒、清场180秒、返航总90秒、逐舰停滞15秒/2米。Stage在Inspector暴露Clock；所有时限按模拟delta推进，暂停不耗时。每波重新安排首架敌舰生成，准备不占清场时限。返航中导引自身失能/超时失败也判整局失败，不再报废后当成功结算。
- 成功返航自动尝试存活舰原有付费维修；金币不足仍可能有伤。基地取消自动维修，有伤且整备时提供手动报价按钮，支付和碰撞/支撑校验沿用现有维修主链。
- 半透明战斗背景、统一冷暖色、矢量双层箭头；波次时限在上方中央，开始按钮底部居中且仅需交互时显示，镜头操作帮助在底部。移除旧施工组件/场景根与BackToBuild按钮；菜单导航保留。

## 验证方式与证据

`CombatHudPlayProbe.RunFlow()`从Main正式加载SiegeGameplay，部署真实舰艇；检查实际Toggle射线/点击、按钮阶段、首架敌舰延迟、友舰真实致命伤、核心真实致命伤、延迟失败面板与清场超时。超时用Play实例Inspector短时限加速，资产默认值不变。

`RunRecovery()`使用只在Play实例配置的真实Finch，经生产部署、真实返航和维修入口，验证船伤自动修复、基地伤势保留与手动维修、次波同样延迟刷新。维修夹具直接消耗规则名额隔离敌舰随机性，不能称为自然战斗清场。90秒/15秒边界通过时钟输入推进；2.1米进展测试移动临时舰艇，只证明进展判定，不冒充原生飞行轨迹。另用冻结真实舰艇、缩短Play实例停滞阈值验证Stage实际失败传播与收益丢弃。

JSON报告与截图存于`Temp/SharedCombatHud`；当前结果见本记录后续验证条目。共享HUD四分辨率离屏预览通过（1280×720、1920×1080、2560×1440、3440×1440），不等同四分辨率自然战斗人工验收。
