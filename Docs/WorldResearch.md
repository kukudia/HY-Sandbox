# 可交互可破坏世界：本轮研究结论

2026-10-15。已实现内容与使用方式见 [WorldLab](WorldLab.md)；以下路线是后续设计建议，不是已实现功能。

## 已建立的可验证基础

WorldLab把规则化体素数据、外露面网格、分块碰撞、工具交互、炮塔伤害和差量存档串成完整实验链。破坏不会创建每格GameObject；静态地形与少量动态金属碎片分开，适合继续研究载具采掘、火炮破坏掩体和建筑失稳。

当前地貌偏方块与台阶，地图有限，遗迹为同类几何组合。它证明数据与交互链可用，尚不能证明场景的美术丰富度、导航质量或完整游戏循环。不要直接把当前研究场景作为Main的世界替换。

## 下一步优先验证的玩法切片

先做一个有限地图中的完整载具任务：出生点→穿过可破坏掩体→命中有支撑的金属桥/塔→脱落改变通路→保存/重开恢复。地形障碍改变行驶路线，金属碎片提供短时物理反馈；采集收益和资源掉落在规则明确后接入现有货仓，不能把体素材质字节当作玩家Block身份。

验收应包含实际驾驶、炮塔遮挡、机器人绕行、爆炸后静态碰撞消失、碎片不穿车、存档往返以及失败后重试。现有炮塔单元回归不能替代这些场景验收。先把这条链跑通，再扩展更多生物群系或无限地图。

## 地貌表达选择

继续使用体素是当前返工较少的路径：断面、洞穴和材料硬度都由已有数据自然表达。下一步可加入岩层厚度、侵蚀状高度场、洞穴密度场和独立分布的遗迹规则；每种规则保留种子与Inspector资产参数。为不同区域增加色彩、岩壁轮廓和散布物，但装饰物必须约定支撑单元被破坏后的生命周期。

如果目标转向光滑岩洞，先独立对比一块相同密度场的Marching Cubes网格与当前方块网格，验证破坏断面、UV、材质、碰撞重建和邻块接缝。不要同时长期维护两套完整世界表示；确定表现目标后再迁移。

## 支撑模型的实际边界

现有六邻接算法把接触任意土/岩当成锚点；悬空土岛也能支撑金属，因此不是地基连通性或应力求解。每次扫描整个有限世界，生成碎片时同步移除源碰撞，规模增大后可能形成主线程尖峰。当前上限控制刚体数量，不等于控制所有扫描/重建成本。

后续先记录真实破坏分布下支撑扫描、片段网格生成、MeshCollider赋值与物理步的P50/P95/最大耗时，再考虑只从破坏邻域更新连通标签或分块支撑图。大结构可先拆成预定义区域；不能靠提高最大碎片格数来模拟全建筑倒塌。所有采样均需区分静态网格、碎片网格、待销毁对象和编辑器中加载的烘焙资产。

## 扩展地图前的门槛

当前128米区域只需32个分块；局部爆破微基准不能外推到公里级世界。扩展前先有受控地图尺度、破坏密度和连续行驶路线的测量，分别记录渲染、碰撞烹饪、GC、常驻内存与主线程尖峰，再选择greedy meshing、后台纯数据计算或流式加载。

后台任务只能处理拥有的纯数据快照；创建/赋值Unity Mesh及碰撞需遵守引擎线程约束。异步结果带分块版本，旧破坏结果不得覆盖新编辑。流式卸载前保存脏差量，并在重载时核验生成器版本/指纹；当前存档拒绝不匹配基线是保护措施，未来更改生成规则需明确迁移策略。

## 本轮未覆盖

未制作主界面、未接入Main载具地图、未做正式Player构建、未完成手动驾驶/碎片接触验收。美术仍为程序化原型材质，没有外部AI资产输入。有限金属脱落、差量存档和后台压力证据均有独立记录，不能合称完整开放世界或无限破坏系统。
