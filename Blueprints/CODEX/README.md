## 脚本

在项目根目录、匹配的 Unity Editor 已连接时运行：

```powershell
unity command eval_file --file Blueprints/CODEX/Generate.cs --timeout 60000 --json
unity command eval_file --file Blueprints/CODEX/Validate.cs --timeout 60000 --json
```

生成器直接读取 Resources 中的真实部件，输出游戏格式 `BlockDataList` JSON；无运行时组件或专用插件依赖。部件 ID 按蓝图和构建顺序确定，可重复生成。已有同名不同内容先创建带时间戳的 `.bak`；用户手改版建议另存名字，避免被重新生成替换。

`RuntimeProbe.cs` 是可选的短时自动游玩探针：Main 场景进入 Editor Play Mode 后调用。它会切换当前运行时蓝图、依次加载五艘、使用现有分组与启动流程，并设置与首次 Space 相同的悬浮状态。为避免编辑器焦点吞掉模拟按键，暂时关闭 ControlUnit 的输入采样，调用其公开移动接口注入前、左、后、右输入；原有供电、推进、受伤与维修逻辑继续运行。临时将敌人间隔设为 5 秒，每艘观察 24 游戏秒，最后退出 Editor Play Mode。不要在进行中的手动游玩或未保存的运行时建造中启动。它不保存场景、不修改敌人蓝图，不应被当作键盘端到端测试、长时间压力测试或人工手感评测。

## 验证边界

- Unity 6000.3.11f1 / Main 场景：五艘均通过实际加载和单一物理连接组检查，依次完成约 24 秒起飞与四向输入观察；采样峰值速度 6.39～6.87，驾驶舱最低耐久 500，未供电部件 0。完整统计见 `Runtime-summary.json`。敌人每 5 秒生成，采样存活敌人数最多 3～5 个，但本轮没有记录持续命中 DPS，因此不能称为密集火力耐久压测。
- Console 未观察到 Error；已观察到维修无人机的 Collider.ClosestPoint Warning，列为下方 P0。探针结束后已退出 Play Mode，Main 场景保持未修改状态。
- `Validation.json`：五份文件的资源、尺寸、ID、真实可用连接点几何、从驾驶舱出发全图连通、供电覆盖和游戏目录副本一致性检查。
- `Runtime.tsv`：自动游玩每秒采样，包括核心耐久、剩余部件、未供电部件、速度、位置和存活敌人数。`completed` 只代表完成短时观察；不代表无限生存，也不代表密集火力下的最优方案。
- 生成器逐占用格拒绝重叠。所有数值来自现有 Prefab。未更改生产代码、场景和游戏平衡。

## 改进建议（优先级）

1. **P0：修复维修无人机避障警告。** 本轮运行实际反复出现 `Physics.ClosestPoint can only be used with a BoxCollider, SphereCollider, CapsuleCollider and a convex MeshCollider`，调用位于 `Bot.CalculateAdvancedAvoidance`（Bot.cs:551）。先过滤不支持的 Collider 或提供正确的替代距离查询，再验证穿障、归巢和维修路径；仅关闭日志不能修复导航。
2. **P0：大蓝图加载与规模性能。** 默认逐部件等待 0.1 秒，737～1081 个部件仅等待就约 74～108 秒。建议按帧时间预算分批实例化、连接图批量构建、合并装甲渲染，并显示阶段进度和取消入口。探针仅临时将等待设为 0，正常游戏加载值未改。
3. **P1：装甲耐久、体积、质量与成本统一。** 1x1x1 和 2x2x2 都是 100 耐久，后者质量却为 8；堆小方块同时提高总耐久、牺牲层数和 CPU 负担。应按材料/体积或有效受击面积制定耐久，再以成本、质量和连接强度约束，避免性能最差的拼法成为最优解。
4. **P1：提供动力预算和操控反馈。** 建造面板增加有效升力/重力、四向加速度、失去最大动力组后的余量、供电覆盖警告；增加可调主动刹车与受损姿态提示，并明显提示首次 Space 起飞操作。总发电足够不能代替覆盖检查，总升力够也不能代替扭矩平衡。
5. **P1：建立可复现的战斗基准。** 固定随机种子、敌人配置、波次预算和出生包围角度，记录每秒实际受击伤害、维修量、失控时间、击杀数和存活时间，再调炮伤、射程和频率。目前按时间持续随机刷敌，难以公平比较蓝图。
6. **P2：维修和供电加入资源取舍。** 原装维修舱没有 Power 负载，维修量为 20/次；应评估维修能源/材料消耗、单目标叠加上限和维修优先级。发电机输出 4000，先用战斗记录校准，再决定是否需要燃料、热量或爆炸隔离机制。
7. **P2：拓展敌人与任务。** 增加绕后、压制升力部件、慢速重炮、追击轻机等不同威胁，以及护送、回收撤离、限重生存等目标；让双体隔离、轻量机动和厚甲防守各有用武之地。

以上平衡建议来自当前实现与自动探针，尚未做多人盲测、长期密集交火比较和大型残骸场景性能剖析。暂不宣称某艘生存时间最长。
