## 使用

在敌人蓝图编辑列表中选择 `CODEX_E*` 可继续编辑；普通游玩时 EnemySpawner 会将目录内有效蓝图加入随机敌人池。若游戏已经启动，请退出并重新进入 Play Mode，让缓存重新读取。文件是现有 BlockDataList 格式；Spawner 自动设置 Enemy 阵营，JSON 不需要额外阵营字段。

```powershell
unity command eval_file --file Blueprints/CODEX_Enemies/Generate.cs --project-path D:/git_projects/Unity/HY-Sandbox --json
unity command eval_file --file Blueprints/CODEX_Enemies/Validate.cs --project-path D:/git_projects/Unity/HY-Sandbox --json
```

生成脚本读取当前 Prefab，拒绝重叠、使用确定性 ID；若同名文件已有不同内容会报错，保留手动编辑。将手改版本另存为新名字后再重建。

## 验证方法与边界

Unity 6000.3.11f1 的验证分为前 15 秒无目标悬停、15～45 秒 AI 追踪、第 45 秒改变目标位置、第 75 秒移走目标并观察至 90 秒（每秒采样 5 次）。结果以 `Flight-summary.json` 为准。

| 雀 | 2.45° | 0.25m | 0.31m/s | 无 |
| 梭鱼 | 1.70° | 0.19m | 0.24m/s | 无 |
| 蝠鲼 | 1.82° | 0.14m | 0.11m/s | 无 |

三艘均通过全部验收。无目标与失去目标后的收敛段最大垂直速度分别为 0.0545/0.0535/0.0535m/s；没有持续下沉。配套代码 `dotnet build HY-Sandbox.sln --no-restore` 通过（0 错误、4 个既有警告）。

验收阈值：无目标的第 10～15 秒及失去目标后的第 85～90 秒垂直速度 ≤0.1m/s；追踪收敛后的第 25～75 秒倾角 ≤5°、高度误差 ≤1m、垂直速度 ≤1m/s，目标持续有效，完整部件与供电维持至 90 秒。`Summarize.ps1` 根据原始数据执行验收。完整精度见 `Flight-summary.json`，PNG 为实际飞行截图。

复测期间未出现新的 Console Error；编辑器启动时曾报告 AssetImportWorker 连接中断/崩溃，此类历史启动消息不计为飞行错误，也未宣称全会话零错误。结束后场景未脏、后台运行设置已恢复。

`Validation.json` 记录三艘的资源、尺寸、唯一 ID、可用连接点几何、供电覆盖和安装副本一致性；生成时另检查占用格无重叠。

`FlightProbe.cs` 必须在 Main 的临时 Play Mode 中执行，会清理当前运行时机体，使用真实 EnemySpawner.SpawnBlockData 创建敌机，检查实际单连通组。玩家靶最初位于探测范围外，第 15 秒移入、第 45 秒换向、第 75 秒移走，观察至第 90 秒。测试场地在高空、各机相隔 240m，临时关闭远距离回收和自动刷怪，关闭测试敌机炮塔以隔离受击因素；不修改升力、功率、质量、PID、阻尼或姿态。完整原始数据在 `Flight.csv`。测试结束退出 Play Mode，不保存场景和现有玩家存档。

**不要在有未保存运行时建造的游玩会话中执行探针。** 蓝图完整时的飞行稳定性不等于驾驶舱、发电机或单侧升力损毁后仍能稳定飞行；本次不保证受损飞行和长时间拥挤战斗稳定性。

稳定飞行补充修复：EnemyController 原先在没有目标时每帧用机体当前位置重设悬浮目标，使下沉时设定点也下移；仅调整部件原点不能解决。此次改为首次无目标/失去目标时记录飞控当前高度，持续保持到再次获得目标，追踪逻辑和部件数值保持原样。因此无目标悬停的验证结论需要配套本次 EnemyController 修复，不能仅复制 JSON 到旧版本后期待相同行为。蓝图飞控 local Y=0，便于保持统一高度参考。
